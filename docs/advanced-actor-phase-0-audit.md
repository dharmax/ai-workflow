## Historical compiler lesson, bounded by evidence

`legacy-reference/code/compiler.ts` is byte-identical to `git show legacy-pre-rewrite:src/compiler.ts` (SHA256 `3af1837f6c1b33c2138476f93464cffc8554c48479d769a39f1fb054a061e38b`). The old CodeletEngine mounts OS execution and every registry capability as text-compiler services, persists compiled wishes, and exposes compile_and_execute through the registry. Its prompt adapter checks Ollama with a 100 ms availability deadline and gives normal synthesis 2,500 ms. It auto-approves logic critique; on unavailable/unsuccessful inference it returns canned intent metadata and a state returning `{status:'completed',ok:true}`.

The replay extracts that **exact method**, changes only TypeScript signature syntax, forces its unavailable branch, and invokes current text-compiler with one explicitly bound project-evidence service. It reproduces success without evidence. Dependencies/runtime are not reconstructed to historical revisions; no claim is made about the quality of a historical model run. Preserved old transcript at commit `fe73087` lacks provider/tool traces and is not counted as proof of live correctness or failure. The directly reproduced adapter defect is enough to reject the inference that compiler sophistication compensates for failed executive/evidence behavior.

## Decisions and smallest next step

- **Model adequacy/latency hypothesis: supported in part.** Remote routes fix selected cases with the current primitives; native ai-cli analysis is substantially slower and fails. Do not generalize two repetitions into reliability, and do not blame every failure on a weak model.
- **Routing alone as the full correction: rejected for tested routes/workloads.** Live AIWF analysis remains ungrounded with both stronger routes; ai-cli selector can terminate before its Actor. Better routing materially helps, but does not reliably fix the class.
- **Evidence acquisition/dispatch hypothesis: supported.** Same mini answers correctly once policy is observed. Terse selector has an ambiguity confound in ai-cli, but explicitly local compound-analysis failure has none. No query-specific loader is authorized by this oracle experiment.
- **Deterministic micro-step coordination as the dominant defect: unsupported.** No compute integration justified. Existing scratch helper works and batching reduces turns without curing grounding. Compiler-first behavior is rejected.
- **System-1 tactical value: unproven.** Successful remote analysis includes unavailable System-1; current assessment is safety/presentation, not a sophisticated-task gate.
- **Stable shared abstraction: existing LLMActor/LLMSession/Asker/ModelRouter are shared and usable; a new higher-level shared policy is not proven.** Dispatch, discovery, authority and context semantics differ. Extracting advanced-actor would currently wrap distinct defects and duplicate ownership. **Package extraction is not justified.**

The smallest next J2.4 implementation candidate is an **ai-cli TurnExecutor evidence-handoff correction**: when an interpreted current-state answer requires workspace evidence and retrieval supplies none, continue through the existing Actor/resource/shell path rather than returning the unsupported draft as success. Keep explicit constraints and safety, reuse existing dispatch, and qualify it against the preserved local-analysis failure plus direct-answer/simple controls. The general evidence rule is shared conceptually; its successful implementation across both hosts has not been proven. AIWF separately needs a bounded experiment exposing actual governing evidence/dependency contracts through existing discovery, with unchanged route, before choosing a production correction. Merely extending prompt clauses or provisioning a global catalog is not supported by the failed metadata hint.

For J2.5 the smallest independently demonstrated correction is to make settings changes update the existing runtime construction and display the effective task target and last-call metrics. This is a host configuration fix using the sole llm-utils router; it is not an advanced Actor architecture. Do not silently combine it with evidence-handoff work in the next experiment.

Stop here. These are implementation candidates, not implemented fixes. Phase 0 does not establish J2.4 reliability or full J2.5 acceptance. Full suites/typechecks were not rerun because no production code changed; live black-box runs, source contracts, independent answer review, diagnostic script execution, source-diff checks and ledger synchronization are the evidence for this audit.
