# Dharmax-way S5 — Story Test-First Lifecycle

## Scope and method

S5 implements the planned Story-test lifecycle only. S4 remains accepted at `docs/dharmax-s4-2026-10-16.md`; this work does not redesign autonomous Ticket resolution (S6), close Gate 5, or change the S4 model-backed route. The S4 proposal route remains unqualified because it returned `authentication: User not found`; it was not retried.

Concepts: accepted Story intent and accepted applicable Aspects define the reviewed contract; the path-keyed `TestNode` holds stable identity and current execution evidence; the real Bun test file remains the executable behavior.

Architecture: S2 Product mutations hold reviewable state/reason and revision basis, the existing Causal Change Engine guards source activation and implementation edits, and the existing `triage_test_failures` runner executes/persists results. Workspace exposes the same status and run operation. No runner, event log, or persistence layer was added.

Flow: materialize a reviewed test as skipped before implementation; starting its addressed Ticket changes that same test to active/not-run; run through the existing runner; classify an assertion failure as expected-red only against the reviewed fixture and current Story/Aspect/test revisions; classify a current passing run green; report malformed or infrastructure failure blocked. Fixture or intent revision changes make prior evidence stale. The existing Ticket implementation guard now requires current expected-red or green evidence.

## DW-04 public Story

**Actor:** Signed-in user saving an avatar after applying a filter.

**Initial State:** A prior avatar exists; the filtered preview is ready. The materialized Bun test is skipped while its Ticket remains Todo.

**Action:** Start Ticket `T` through the public Ticket-state operation, then use Workspace’s “Run active Story test” operation before implementation. The test first asserts the happy save result, resets the prior value, then attempts a failing write and asserts the thrown error and preservation of the prior value.

**Expected observable result:** Ticket start activates `test:tests/dw04-save.test.ts` in place. Before implementation the happy-path assertion succeeds, then the prior-value assertion fails against the deliberately faulty fixture and is classified expected-red. A guarded fixture repair makes that same test green. A syntax-broken fixture is blocked, not expected-red; repairing it permits a new green run. The independent backlog Story retains its own skipped TestNode. Updating the applicable accepted Aspect makes the prior green evidence stale, including after reopening the canonical store.
