# AI-Workflow (AIWF)

**AI-Workflow is the AI-assisted engineering workflow, and the software that operates it, built to follow [Dharmax-way](dharmax-way.md).** It operates under the mandatory [Product charter](product.md): downstream product definitions are reviewed for conflict/drift and require a developer answer to material warnings. It then takes approved intent through concrete [User/Actor Stories](user-story.md), executable [tests](test.md), justified [Tickets](ticket.md), engineering operations and independent verification to working product behavior.

AIWF maintains connected project state in the [Project Graph](project-graph.md) and repository, so its work and evidence can be inspected and resumed without reconstructing a chat. Its operations serve the workflow rather than making records the goal. **Process** proposes/reconciles product intent; **resolve** is the primary work-execution entry point, internally coordinating readiness triage, substantive read-only investigation, optional preparation, guarded implementation, real tests and independent acceptance. The [native operation responsibility contract](../../plans/AIWF-DHARMAX-WAY-DESIGN.md#33-native-work-lifecycle--responsibility-contract-developer-decision-2026-10-25) defines their boundaries and known implementation gaps; it does not claim the current code has fully achieved them.

The central obligation is **to make the approved US test pass through correctly engineered work**, while preserving the developer's authority, applicable Aspects, Rules, authorization and valid evidence. For a multi-component US, an optional separate full-flow skeleton test may demonstrate the connected path using temporary internal stubs. Every such stub immediately has a coding Ticket for its real replacement/removal; the skeleton's success is never US acceptance. Other smaller coding Tickets remain justified by actual missing work.

Dharmax-way is the governing approach; AIWF implements and supports it. The current code is being brought into alignment with this target: this definition does not claim every stage is already implemented. See [current architecture](../architecture.md) and [governing design](../../plans/AIWF-DHARMAX-WAY-DESIGN.md).
