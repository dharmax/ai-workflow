## Changed owners

- src/workspace/server.ts: loopback HTTP adapter. Existing list/get tools supply product/work views; existing store reads supply exact edges and versions. Product-only schemas reuse ProductMutationSchema and ProductRevisionSchema. Preview and acceptance delegate to preview_change/apply_change, preserving admission, fingerprint and native atomic batch behavior. Source-edit actions are refused at this boundary. A per-session capability URL, independent CSP nonce, origin/Host checks, no-store responses and bounded request body protect the local session. Caller retains store ownership.
- src/workspace/client.js: ephemeral presentation state, product/work search, entity navigation, dedicated Feature/Aspect/Story forms, explicit definition status and revision, legacy scenario review, relationships and applicable accepted Aspects. Editing invalidates the review; asynchronous responses cannot reactivate an older edited/navigation state. Saves lock controls until completion. Stale editors retain their text.
- Proposal review: original request, field-level before/after diff, relationship mutations, known impact/warnings/dependents, editable dedicated fields, advanced complete request editor, accept/reject/cancel. Imported stale fingerprints are refused instead of silently renewed. Existing Feature links survive unrelated Story edits; changing the Feature selector is a deliberate reviewed relationship change.
- src/workspace/page.ts: one bundled responsive presentation with labels, keyboard navigation, visible errors and ordinary document flow; action bars do not obscure editor fields. Ctrl/Command K searches, Ctrl/Command S reviews, Escape cancels review.
- src/cli.ts: workspace [port], printed local session URL and signal-based shutdown. No automatic provider or implementation operation.
- src/entity-view.ts: shared CLI/shell read view now exposes S1's explicit Story Intent/State/Action/Result/Exceptions/Bounds and definition-review state. These added read fields do not introduce another editor mutation path.
- tests/dharmax-s3.test.ts and package.json: repeatable real Chromium journeys using Bun tests, isolated temporary databases, actual CLI subprocesses and actual stdio MCP. Playwright is a development dependency; install its Chromium once as documented in README.
