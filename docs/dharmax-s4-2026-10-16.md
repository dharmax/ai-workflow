## Implemented behavior

- Accepted Feature intent can be reconciled into proposed complete Stories, a delivery Epic, and Tickets with explicit Story, architectural-scope, priority, and Epic relationships. Feature-only scopes are refused for this flow. New Story scenarios require Actor, Intent, Initial State, Action, and Expected Result. Applicable accepted Aspects remain the source of authority.
- Repeated definitions retain identity and content unless a reviewed `revise` is explicit. Same-title/different-identity and scenario ambiguity returns a required decision. A developer can edit fields in Workspace before approval. Rejecting a proposed Story and its exclusive Ticket leaves neither canonical object behind.
- Story-test preparation inspects a real fixture and named public export, emits an executable Bun test calling that export and asserting an observable result, and checks source syntax and indexed subject/assertion calls. The source diff and canonical Test link are separately reviewed. Test identity is the existing path-keyed `test:<normalized path>` TestNode.
- A missing fixture or public interface is uncovered. A materialized skipped test is allowed only before implementation begins. If work has started, generated test source is active (`not-run`) rather than skipped. Ticket implementation is refused while an accepted addressed Story is uncovered or still skipped; activation/execution lifecycle remains S5.
- Source creation/indexing and DB approval are reported as distinct outcomes. If source materialization succeeds but TestNode linking does not, the file and canonical indexed identity are retained, no Story-test approval is claimed, and the user is directed to prepare a fresh review against that identity. No rollback or transaction framework spans filesystem and DB.
