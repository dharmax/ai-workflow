# AIWF Agency Constitution

**Authority:** architectural invariant for every Actor, System-1, discovery, skill, compiler, code-writing, routing and execution change.

AIWF wraps a general reasoning model. Infrastructure must make that model more capable, grounded, safe and efficient — never reduce solvable goals to a pre-enumerated catalog, one preferred execution mechanism, or a pile of duplicated cognitive paths.

## Constitutional rules

1. **The Actor is the general problem solver.** The user supplies a goal. The Actor determines what it needs to know or do, chooses useful means, gathers evidence, acts, observes, replans and finishes.

2. **Goal precedes strategy; strategy precedes capability.** Never begin architecture from “which tool handles this phrase?”. Begin from the actor outcome and required evidence/actions.

3. **Actor journeys precede product capabilities.** Product development starts from concrete narrative journeys. Capabilities, APIs, architecture and tests derive from those journeys. Pure technical maintenance may remain direct Ticket work.

4. **General knowledge is valid methodology; project facts require evidence.** Model knowledge may determine *how* to solve a problem. Claims about the current repository/project/runtime require observed evidence or valid derivation from observed evidence.

5. **System-1 advises; it never governs.** Cheap tactical assessment may describe task shape, evidence needs and promising means. It cannot permit/forbid a goal, shrink available powers, force one route, or establish final project truth.

6. **Discovery is optimization, never a competence boundary.** Failed/empty/misleading semantic discovery may reduce convenience, not make an otherwise solvable goal impossible.

7. **Bootstrap competence is plural.** The Actor may need universal environment execution, capability acquisition, reusable know-how acquisition, deterministic composition, code writing, or external knowledge. No single one is “the universal solution”.

8. **Skills, capabilities, codelets and code writers are distinct.**
   - Skill = reusable know-how/procedure.
   - Capability = operation or evidence source.
   - Codelet = deterministic executable composition.
   - Canonical code writer = AIWF source-generation capability for grounded repository implementation.
   Keep these semantic distinctions.

9. **One canonical AIWF source producer.** Nontrivial new/replacement repository source generated by AIWF must go through the canonical `write_code` path backed by text-compiler. Do not maintain direct prompt synthesis, Actor-authored replacement source, and compiler-backed source generation as parallel implementations. Deterministic rename/refactor/source actions may bypass generative synthesis.

10. **text-compiler synthesizes; CausalChangeEngine mutates.** text-compiler must not become a second repository editor. Repository mutation remains under the existing ChangeEngine/fingerprint/authority contract.

11. **Self-extension is first-class and ephemeral by default.** Missing deterministic composition may be compiled for the run. Persistence/promotion requires reuse evidence or explicit intent. One-off helpers do not silently become durable skills/codelets.

12. **Generated artifacts are not source evidence.** Generated source, tests, examples and scratch data can support synthesis/verification, but cannot establish facts about the current project before they are validly applied/observed. Derived facts retain input provenance.

13. **Generated code obeys the same execution authority.** No compiler/codelet/source-generation path may bypass cancellation, filesystem authority or safety boundaries by executing generated code through an ambient side door.

14. **Modes optimize; they do not define competence.** DEV/PRODUCT/DESIGN/TRIAGE influence preferences, not the set of goals the Actor may attempt.

15. **Optimizations may not become prerequisites.** Registry ranking, System-1, semantic tags, skills, cached context, specialist tools and model routing are aids unless the goal genuinely depends on them.

16. **Failure is evidence, not surrender permission.** AIWF may claim inability only after the concrete required dependency is inaccessible, unsafe, unauthorized, or requires user input. A missing specialized tool is not itself a blocker.

17. **No phrase-shaped architecture.** Never add production logic for “second”, “least”, “critical path”, a particular acceptance prompt, or another linguistic symptom when general reasoning/composition solves the class.

18. **Hard safety cannot live only in prompts.** Skills and system prompts guide behavior; leases, ToolContext authority, ChangeEngine validation, dirty-target protection, tests and acceptance enforce it.

19. **Outcome proves agency.** Classifier/tool/unit tests prove mechanisms. General competence is accepted only through realistic actor journeys plus independently checked truth.

## Degradation law

Disable or break any one optimization — System-1, semantic discovery, a specialized skill, a helper compiler route — and AIWF should either find another reasonable path or name the concrete dependency that truly became unavailable.

For generative repository source, text-compiler may legitimately be a required dependency once `write_code` is canonical; failure must then be reported explicitly rather than silently falling back to a duplicate ad-hoc source generator.

## Merge law

Any Actor/discovery/skill/compiler/code-writing/routing change that violates this constitution or the current Agency Gate in `docs/agency-restoration-plan.md` must not merge as completed restoration.

When an optimization conflicts with agency, agency wins.  
When a duplicate mechanism conflicts with the Prime Directive, the simplest canonical path wins.
