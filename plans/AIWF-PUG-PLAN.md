## Discipline across P0–P5

- Follow Concepts -> Architecture -> engineering Flow -> whole affected Implementation and inspect immediate callers before editing. Write executable public journey/red first for new behavior; fix root cause; run focused then stage gates.
- All Product edits through single guarded reviewed/versioned mutation owner, including CLI direct commands, interactive shell, Workspace and MCP. File and DB effects remain separate; never claim cross-resource atomicity.
- An existing product can have multiple Goals and modules; don't make a mandatory hierarchy or pseudo-feature for pure maintenance. A Story's accepted definition is not satisfaction; a Bug's report is not proof; a green test is not Feature/release approval.
- One narrow owner change per observed defect. Keep existing architectures. Provider auth failure is a provider blocker, not product red and does not authorize retries/budget expansion.
- Every checkpoint reports: source HEAD and dirty state, exact changed owners, Story initial/action/observed, skipped/blocked counts, focused and regression results, negative tests, residuals and next-stage go/no-go. Do not auto-advance.
